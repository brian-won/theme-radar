# daily-market-report

한국 주식 일일 시황·주도 테마 리포트를 생성해 "테마 레이더" 대시보드까지 최신화하는 전체 절차입니다.

> **Notion 기록 단계는 2026-10-20부로 이 스킬에서 제거했습니다**(사용자 요청 — 필요해지면 그때 다시 절차를 추가할 것, 지레짐작으로 되살리지 말 것).

## 언제 사용하는가
- 사용자가 특정 날짜(보통 "오늘")로 시황/종목 스크리닝을 다시 돌려달라고 할 때
- 그 결과로 일일 리포트를 만들어달라고 할 때
- 테마 통계 대시보드를 최신 데이터로 갱신해달라고 할 때

## 사전 준비 (최초 1회, 세션마다 재확인)
아래 환경변수가 없으면 사용자에게 `!` 명령으로 직접 설정해달라고 요청할 것 — 절대 비밀번호/키를 채팅에 대신 입력하지 말 것(AGENTS.md 4장).
- `KRX_ID`, `KRX_PW` — data.krx.co.kr 무료 회원 (pykrx 인증용)
- `KIS_APP_KEY`, `KIS_APP_SECRET` — 한국투자증권 모의투자 Open API 키 (당일 조회 시 KRX+넥스트레이드 애프터마켓 통합 보정용, `scripts/kis_client.py`가 사용)

## 절차

### 1. 스크리닝 실행
```bash
python scripts/market_screen.py [YYYYMMDD]   # 생략 시 최근 영업일
```
- pykrx로 시가총액 300억+, ETF/ETN/스팩/우선주 제외 후 (거래대금, 등락률) 캐스케이드 임계값(500억/3% → 500억/2% → 300억/2%, 20종목 초과 시 완화 중단)으로 스크리닝.
- 조회일이 당일이면 KIS API로 KRX+NXT 통합(애프터마켓 포함) 수치로 자동 보정됨 — `docs/product-spec.md`의 배경 설명 참고.
- 결과 JSON에 `index`(코스피/코스닥 등락률·거래대금·이평선), `applied_screen_tier`, `stocks`(테마/재료는 비어있음) 포함.

### 2. 테마/재료 리서치
- 스크리닝된 종목마다 WebSearch로 당일 상승 이유를 조사하고 테마명을 부여. **테마명은 인포스탁(infostock.co.kr) 표기를 우선** — 국내 증권 뉴스가 "인포스탁 기준 OO 테마" 식으로 그대로 인용하는 경우가 많으니 검색 결과에서 활용. 마땅한 표기가 없으면 합리적으로 제안(사용자가 나중에 직접 교정 가능).
- **상승 이유 출처 규칙(2026-10-26 사용자 지시)** — 조회 날짜에 따라 다르다:
  - **당일 스크리닝**: 인포스탁 무료 회원은 전일자까지만 조회되므로 **전체 뉴스를 검색**해 내용을 요약해서 재료로 쓴다. 언론사 간 우선순위는 두지 않는다(여러 기사를 종합해 요약).
  - **지난 날짜 스크리닝**: **인포스탁 '특징 상한가 및 급등종목'을 우선**으로 찾고, 거기 없는 종목만 전체 뉴스 검색으로 보완한다.
  - 인포스탁은 **검증 용도**다 — 당일에 뉴스로 쓴 재료가 맞는지 다음 날 이후 인포스탁으로 대조할 때 쓴다.
  - 어느 출처에서도 확인 못 하면 reason 끝에 "(추정)"을 붙인다.
  - 네이버 카페는 사용하지 않는다(사용자 결정. Claude in Chrome이 cafe.naver.com 접속을 안전 정책으로 차단하기도 함).
  - **인포스탁 접근**: 종목 페이지(`/Company/Features` 특징종목, `/Company/JumpSlumpReason`, `/Company/TodayIssues` 등)는 로그인 필요 — WebFetch/헤드리스로는 "로그인이 필요합니다"만 보인다. **사용자가 로그인해 둔 크롬을 Claude in Chrome으로 읽는다**(새 탭을 열어 읽고 다 쓰면 내가 연 탭만 닫기). 인포스탁이 필요한 작업(지난 날짜·검증)은 **검색을 시작하기 전에 먼저 로그인 상태를 확인하고, 로그아웃이면 사용자에게 로그인을 요청한 뒤 기다린다.** 비밀번호는 절대 받거나 입력하지 않는다. Claude in Chrome이 없는 도구(코덱스 등)는 사용자에게 알리고 뉴스 검색으로 진행.
- 재료는 한 줄 요약, `reference/테마일지_9월.xlsx`의 "재료" 컬럼 문체를 참고.
- 종목 수가 많으면(10개 이상) WebSearch 결과로 컨텍스트가 오염되니 **fork 서브에이전트에 위임**하고 결과만 받을 것 — 3~4단계까지 fork에 함께 맡기는 게 효율적.

### 3. 테마 그룹핑/순위화
- 테마별로 묶어 평균 등락률, 합계 거래대금(억원, 정수) 계산.
- **합계 거래대금 기준 내림차순 순위** — 1~3등은 개별 순위(`rank: 1~3`)로 표시(`reference/테마일지_9월.xlsx`의 `일별주도섹터`/`260105(월)` 시트와 동일 규칙). **통계(발생빈도 등)는 1~3등만 집계 대상**이라 이 셋의 경계는 엄격히 지킬 것.
- **4등 이하도 하나로 뭉뚱그리지 말고 반드시 테마별로 세분화**해서 `rank: 4`의 여러 그룹으로 나눠 담을 것(거래대금 낮은 종목이라도 어떤 테마였는지 대시보드 리포트에서 확인 가능해야 함 — 2026-09-18 사용자 요청 이후 표준 규칙). `sumValue` 내림차순 정렬. (예: `daily_detail_with_reasons.json`의 "2026-09-17" 키 참고 — 항공우주/게임/광통신/바이오 등으로 세분화된 사례)
- **큰 틀(인포스탁 테마) / 작은 틀(세부 테마) — 2026-10-22 개편**: daily_detail의 그룹 `theme`은 그날의 구체적인 **작은 틀** 이름이고, 대시보드는 `data/theme_taxonomy.json`의 `mapping`(작은 틀 → 큰 틀)으로 다시 묶어 **큰 틀 단위로 1~3위를 매긴다**(대시보드 JS `buildFrameDetail()`, 리포트·테마·관심종목·통계 탭 모두 이 기준). 큰 틀 이름은 인포스탁 'Daily 특징 테마'(https://www.infostock.co.kr/Theme/DailyFeaturedTheme, 로그인 없이 목록 제목 열람 가능)에 실제로 쓰인 표기를 따른다.
  - 새 작은 틀이 생기면 **반드시 `theme_taxonomy.json`의 `mapping`에 큰 틀을 지정**할 것(빠지면 `build_dashboard.py`가 경고를 출력하고 작은 틀 이름이 그대로 큰 틀로 표시됨). 맞는 인포스탁 큰 틀이 없으면 **사용자에게 큰 틀 이름을 확인받고** 추가(2026-10-22 사용자 지시). 사용자 승인으로 추가된 큰 틀: 신규상장(IPO), 지주사/밸류업, 게임, LED, 품절주, 경기방어주, AI 소프트웨어/플랫폼, 기타.
  - 한 종목이 같은 날 여러 작은 틀에 해당하면 **각 작은 틀 그룹에 중복 기재해도 됨**(사용자 지시). 큰 틀 합계·평균은 대시보드가 종목 중복을 빼고 계산한다.

### 4. "테마 레이더" 대시보드 갱신
두 가지 버전이 공존한다. 데이터 원본은 동일(`data/daily_reports.json` + `data/daily_detail_with_reasons.json`)하므로, 새 날짜 추가 시 두 버전 다 갱신할 것.

**4-A. 표준(공통) 버전 — `dashboard/index.html` (Claude/코덱스/안티그래비티 등 어떤 도구로도 사용 가능)**
- `data/daily_reports.json`에 그날 리포트 요약(코스피/코스닥 등락률·거래대금·이평선, 종목수, top1~3) 항목 추가. `notionUrl` 필드는 Notion 기록을 하지 않는 한 생략할 것(대시보드는 없으면 링크를 `#`로 비활성 처리함).
  - **`kospiMaD`/`kosdaqMaD`(2026-10-22 추가, 필수)**: 시황 표의 5·20·60일선 화살표가 쓰는 구조화 필드. `[{"w":5,"pos":"위"|"아래","dev":<이격도%, 소수 둘째자리>}, {"w":20,...}, {"w":60,...}]` 형식 — `scripts/market_screen.py`의 `index.KOSPI.ma`(각 윈도우의 `value`+`position`)와 `index.KOSPI.close`로 `dev = (close-ma.value)/ma.value*100`을 계산해서 채울 것(기존 문자열 `kospiMa`/`kosdaqMa`는 상세카드에서 계속 쓰므로 그대로 둘 것).
- `data/daily_detail_with_reasons.json`에 그날 전체 상세(순위별 테마 그룹 + 종목별 종목명/등락률/거래대금/재료 `reason`)를 날짜 키로 추가.
  - ⚠️ **발생빈도 = 테마에 속한 종목 수가 아니라, 그 테마가 어떤 날의 1~3위로 뽑힌 횟수다.** 4등 그룹은 통계에서 제외되지만, `daily_detail`에는 4등 종목도 전부 기록한다(상세표 표시용).
- `python scripts/fetch_recent_prices.py` 실행 → 관심종목 탭의 최근 5거래일 시세와 코스피/코스닥 구분을 `data/recent_prices.json`에 갱신(새 날짜를 추가한 뒤 빌드 전에 항상 먼저 실행. KRX_ID/KRX_PW·KIS_APP_KEY/KIS_APP_SECRET 필요. 시세는 KIS 기간별 시세 API를 KRX+NXT 통합(UN) 기준으로 조회하며 172종목 기준 약 3분 소요, 모의투자 초당 2건 제한. 종목명은 공백·&·괄호를 뺀 표기로 pykrx와 매칭하며 미매칭·조회 실패 종목은 로그로 출력됨).
- `python scripts/build_dashboard.py` 실행 → `dashboard/index.html`(로컬 미리보기)과 `docs/index.html`(GitHub Pages 배포본, 내용 동일)을 재생성. 이 파일은 데이터가 내장된 완전한 정적 HTML이라 서버/네트워크/Claude API 없이 더블클릭만으로 어떤 브라우저·어떤 AI 도구에서도 열람/수정 가능하다.
- **실제 서비스(웹/폰)에 반영하려면 빌드만으로 끝나지 않고 `git add -A && git commit && git push`까지 해야 한다** — `https://brian-won.github.io/theme-radar/`는 GitHub Pages가 `main` 브랜치 `docs/` 폴더를 서빙하는 것이라, 푸시 전까지는 로컬 파일만 갱신된 상태다.
- HTML 골격/스타일/JS 로직을 바꿀 때는 `dashboard/template.html`(`/*__SNAPSHOT__*/` 플레이스홀더 포함)을 고치고 다시 빌드할 것 — `dashboard/index.html`을 직접 수정하면 다음 빌드 때 덮어써진다.
- 발행 전 `node --check`로 인라인 `<script>` 문법을 검증하고, DOM을 최소 스텁으로 채운 Node에서 `computeThemeStats`/`groupDetailTable` 같은 핵심 함수를 직접 호출해 종목 수 합계 등을 검산할 것.
- **화면 구조(2026-10-22 개편, D3.js v7 차트)**: 왼쪽 세로 메뉴(시황/리포트/테마/관심종목/통계/분석, 900px 미만에선 상단 가로 메뉴) + 오른쪽 본문(화면 전체 폭) + 상단 통합 검색(종목명·큰 틀·작은 틀·재료, 결과는 '날짜 · 큰 틀 › 작은 틀 (그날 큰 틀 순위)', 클릭 시 리포트 탭 이동). D3는 `dashboard/vendor/d3.v7.9.0.min.js`를 빌드 때 HTML에 통째로 내장(`<!--__D3__-->` 자리)해서 인터넷 없이도 그려진다. **시황 탭**: 월 선택은 `‹ [년월 드롭다운] ›`(리포트 탭과 공용 `renderMonthNav`), 표는 거래일만 오름차순(주말·공휴일 없음)으로 일자 | 코스피(등락률·거래대금·5일선·20일선·60일선) | 코스닥(같은 5칸) 11칸을 가로 스크롤 없이 한 번에 표시, 등락률 칸 분홍/연파랑·거래대금 초록 데이터바(엑셀 서식 계승), 5·20·60일선은 **각각 별도 칸**에 SVG 화살표 하나(`maArrowHtml`, 글씨 없음, 위=빨강/아래=파랑, 2026-10-26부터 화살촉 크기는 고정이고 **길이만 이격도 비례**, 흐린 화살표 위로 진한 화살표가 밑동→끝으로 차올랐다 사라지는 애니메이션, `kospiMaD`/`kosdaqMaD` 사용). 같은 칸 오른쪽 위에 **골든크로스=금빛 별 / 데드크로스=해골** 배지(`maCrossMap`, 직전 거래일 대비 5·20일선·20·60일선 위아래가 뒤집힌 날, 짧은 이평선 칸에 표시 — 이평선 값=종가/(1+이격도)라 이격도만으로 판정). 세 칸 바탕은 **정배열=금색 / 역배열=보라회색**(`maAlignBg`, 2026-10-26): 5일 칸+20일 칸 왼쪽 절반=5·20일선 관계, 20일 칸 오른쪽 절반+60일 칸=20·60일선 관계, 두 쌍이 같은 방향(완전 정배열/역배열)이면 진한 색. 차트는 사용자가 고른 **A2안(위: 등락률 묶음 막대, 아래: 거래대금 꺾은선 + 코스피·코스닥 각각 그 달 평균 점선(오른쪽 여백에 값), 같은 날짜 축)**이고 막대 끝·점마다 수치 표시, 크로스헤어 툴팁, 선택 날짜 강조 띠, 차트 클릭으로 날짜 선택(`marketComboChart(container, rows)`). 지수 색 토큰 `--idx-kospi`/`--idx-kosdaq`. **리포트 탭**: 주도 테마 칩·상세 모두 큰 틀 기준, 상세는 큰 틀(1~3위 개별, 나머지 4등 각각) → 작은 틀 소그룹 → 종목(재료) 순. - **`daily_detail_v2` 컬렉션**에 `doc_id`=날짜로 그날 전체 상세(순위별 테마 그룹 + 종목별 종목명/등락률/거래대금/재료 `reason`)를 저장. 테마 통계(발생빈도/평균등락률/평균거래대금)는 별도 컬렉션 없이 대시보드 JS가 이 `daily_detail`에서 **1~3위 그룹만** 걸러 그때그때 재계산한다(`computeThemeStats()`).
  - ⚠️ **발생빈도 = 테마에 속한 종목 수가 아니라, 그 테마가 어떤 날의 1~3위로 뽑힌 횟수다.** 4등 그룹은 통계에서 제외되지만, `daily_detail`에는 4등 종목도 전부 기록한다(상세표 표시용, 사용자가 재료까지 보고 싶어함 — 2026-09-16 요청 반영).
  - HTML의 `SNAPSHOT.dailyReports`/`SNAPSHOT.dailyDetail`에도 같은 내용을 정적 스냅샷으로 넣을 것(최초 로드 시 DB 연결 전에도 보이도록). 종목이 많으면 손으로 옮기지 말고 Python으로 JSON을 만들어 HTML 안의 해당 블록을 통째로 치환하는 식으로 하는 게 오타가 안 난다.
  - **기존 문서를 덮어쓸 땐 `ArtifactData`로 먼저 `action:"get"`해서 `version`을 확인하고, 그 값을 `if_version`으로 넘겨 `set`/`update`할 것** — 버전 없이 기존 문서를 쓰면 `version_mismatch`로 거부된다. (과거엔 이 옵션을 못 찾아 컬렉션명에 버전 접미사를 붙이는 우회를 썼다 — `daily_detail`→`daily_detail_v2`가 그 흔적. 지금은 `if_version`이 정석.)
- HTML을 고치는 경우, 발행 전 `dataviz`·`artifact-design`·`artifact-capabilities` 스킬을 먼저 로드할 것(색상/타이포/레이아웃/DB 사용법 규정). 발행 전에는 `node --check`로 인라인 `<script>` 문법을 검증하고, DOM을 최소 스텁으로 채운 Node에서 `computeThemeStats`/`groupDetailTable` 같은 핵심 함수를 직접 호출해 종목 수 합계 등을 검산할 것.
