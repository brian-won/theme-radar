# us-kr-sector-mapping

미국 섹터별 주요 종목과 사업상 연결된 한국 종목을 정리한 매핑표를 읽고, 고치고, "Won's 투자" 대시보드 **관심종목(해외)** 탭에 반영하는 절차입니다.

## 언제 사용하는가
- 미국 종목·섹터와 연결된 한국 종목을 물을 때(또는 그 반대)
- 매핑 행(세부 섹터)·종목·연결강도·근거를 추가/수정/삭제하라고 할 때
- 일일 스크리닝에서 상승 이유가 전일 미국장 이벤트(하이퍼스케일러 설비투자, 머크 실적, 미국 원전주 급등 등)와 이어지는지 확인할 때 — 아래 "이벤트 트리거" 참고

## 데이터 위치
- 매핑 원본: `skills/us-kr-sector-mapping/references/us_kr_sector_mapping.md` (이 파일 하나가 유일한 원본)
  - `## 매핑표`: 1행 = 1개 세부 섹터. 열: `id | 섹터 | 세부섹터 | 미국 종목(티커) | 한국 종목 | 연결강도 | 근거·비고`
  - `## 이벤트 트리거 (시차 매매 참고)`, `## 미확인·주의 항목`: `- ` 목록. 끝에 `(6-1)`처럼 id를 붙이면 대시보드에서 그 섹터 카드 아래에 표시된다(id가 없으면 탭 하단 공통 안내로 표시).
- 표를 읽는 규칙(티커 표기, 연결강도 값, [사실]/[추론] 구분)은 원본 파일의 `## 읽는 법` 절을 따른다.

## 조회
1. 원본 파일을 열어 해당 섹터/종목 행을 찾는다(티커·종목명으로 grep).
2. 답할 때 연결강도는 **사업상 연결의 정성 판단이지 주가 상관계수가 아님**을 함께 밝힌다.
3. `## 미확인·주의 항목`에 걸린 내용(예: 넷플릭스–스튜디오드래곤 계약 조건 미확인)은 확정 사실처럼 말하지 않는다.

## 수정 절차
1. 원본 파일의 표 형식을 그대로 지킨다 — 열 7개, 구분자 `|`, 여러 종목은 `, `(쉼표+공백), 미국 종목은 `이름(티커)`.
   - 미국 대응주가 없으면 `(설명)` 하나만 적는다. 예: `(미국 상장 순수 대형 CDMO 없음)` / 한국 쪽도 같음: `(마땅한 대응주 없음)`.
   - 연결강도는 `강함` / `중간~강함` / `중간` / `약함~중간` / `약함` / `테마성` 중 하나(대시보드 배지 색이 이 값으로 정해짐).
   - id는 `{섹션번호}-{세부번호}`. 새 섹션을 만들면 frontmatter `scope`도 갱신.
2. 새 사실은 웹 검색으로 확인한 것만 `[사실]`로 적고, 해석은 `[추론]`. 확인 못 한 것은 `## 미확인·주의 항목`에 추가.
3. frontmatter `as_of`(기준일)와 `row_count`(실제 표 행 수)를 갱신.
4. `python scripts/build_dashboard.py` 실행 → 출력의 `관심종목(해외) 매핑 N행`이 기대 행 수와 같은지 확인.
5. 커밋·푸시는 사용자가 요청할 때만.

## 대시보드 연결 (참고)
- `scripts/build_dashboard.py`의 `parse_us_kr_mapping()`이 빌드 때 원본을 읽어 `SNAPSHOT.usKrMap`으로 HTML에 내장한다(파일이 없으면 탭이 빈 안내만 표시).
- 화면(트레이딩뷰 워치리스트 형태): 탭 = 섹터, 카드 안 = 세부 섹터별로 미국 종목 행(티커·이름·최근 5거래일 등락률/거래대금) → 그 아래 `국내` 참조 행(한국 종목 최근 5거래일 등락률/거래대금) → `+ 국내 종목 추가` 버튼. 연결강도·근거·이벤트 트리거·미확인 항목은 화면에 표시하지 않는다(원본 파일에만 유지).
- 시세: 미국은 `python scripts/fetch_us_prices.py`(→ `data/us_recent_prices.json`), 국내는 `python scripts/fetch_recent_prices.py`(매핑표 한국 종목도 조회 대상). 매핑표에 종목을 추가했으면 두 스크립트를 다시 돌린 뒤 빌드해야 시세가 붙는다. 국내 종목명이 pykrx 표기와 다르면(예: 네이버→NAVER) `fetch_recent_prices.py`의 `NAME_ALIAS`에 추가.
- 화면에서 추가·삭제한 국내 연관 종목은 관심종목(국내) 수정과 같은 저장소(브라우저 localStorage + Supabase `watch_state`의 `usAdded`/`usRemoved`, 키 = 세부 섹터 id)에 저장되고 원본 파일은 바뀌지 않는다. 영구 반영하려면 원본 매핑표에 옮겨 적는다.
