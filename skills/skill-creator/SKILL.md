# skill-creator

새 스킬을 만들거나 기존 스킬을 개선할 때 따르는 절차입니다.

## 언제 사용하는가
- 사용자가 "OO 스킬을 만들어줘"라고 요청할 때
- 현재 대화에서 방금 수행한 작업 절차를 "스킬로 저장해줘"라고 요청할 때
- 기존 스킬의 발동 조건(트리거)이나 내용을 수정/최적화해달라고 요청할 때

## 절차

### 1. 의도 파악
다음을 확인한다.
- 이 스킬이 에이전트에게 무엇을 하게 만들어야 하는가?
- 언제 발동되어야 하는가(어떤 사용자 표현·상황에서)?
- 기대하는 출력 형식은 무엇인가?

현재 대화에 이미 캡처할 만한 절차가 있다면(예: 방금 한 작업을 스킬로 만들어달라는 경우) 대화 기록에서 단계·입출력 형식을 먼저 추출하고, 빠진 부분만 사용자에게 확인한다. 짐작으로 채우지 않는다(AGENTS.md 1장 원칙과 동일).

### 2. SKILL.md 작성
- 위치: `skills/<스킬-이름>/SKILL.md` (폴더명은 kebab-case)
- YAML frontmatter에 `name`, `description`을 반드시 포함한다.
- **description은 트리거 조건과 하는 일을 모두 담고, 다소 적극적으로(pushy) 작성한다.** 예: "PDF에서 표를 추출한다"보다 "PDF에서 표/데이터를 추출할 때 이 스킬을 반드시 사용하라. 사용자가 'PDF', '표', '데이터 추출'을 언급하면 항상 확인할 것"처럼 구체적으로 쓴다. 설명이 애매하면 에이전트가 스킬을 놓치는 경우(undertriggering)가 더 흔하다.
- 본문에는 실제 절차, 예외 처리, 참고할 파일 경로를 적는다. SKILL.md 본문은 가능하면 500줄을 넘기지 않는다(점진적 공개 원칙 — AGENTS.md를 60~80줄로 제한한 것과 같은 이유).
- 세부 참고자료가 길어지면 SKILL.md에 다 넣지 말고 `skills/<이름>/references/`로 분리하고, SKILL.md에는 "언제 그 파일을 열어야 하는지"만 짧게 안내한다.
- 반복 실행되는 결정적 작업(포맷 변환, 검증 스크립트 등)은 `skills/<이름>/scripts/`에 실행 코드로 넣고, SKILL.md에서는 그 스크립트를 실행하라고만 지시한다.

### 3. 기존 스킬 수정 시
- 기존 폴더명과 `name` 값을 그대로 유지한다(임의로 버전 접미사를 붙이지 않는다).
- 변경 후 관련된 다른 기능이나 스킬에 영향이 없는지 확인한다(회귀 확인).

## 도구별 주의사항 (하네스 3사 공통 워크스페이스 기준)
- **클로드 코드**: `description`을 근거로 자동 판단해 스킬을 불러온다(신뢰도 높음). 다만 아주 단순한 요청은 스킬 없이 바로 처리될 수 있으므로, 실질적인 작업에만 트리거되도록 description을 구체적으로 쓴다.
- **안티그레비티**: SKILL.md 구조를 인식하지만 자동 트리거 신뢰도는 클로드 코드만큼 확인되지 않았다. 필요하면 사용자가 `@스킬이름`으로 직접 호출하는 방법도 함께 안내한다.
- **코덱스**: 스킬을 자동으로 탐색하는 네이티브 기능이 없다. `AGENTS.md`에 "필요하면 `skills/` 폴더를 확인하라"는 텍스트 지시가 있어야만 참조되며, 이 지시 없이는 이 스킬 생태계 자체가 코덱스에서 작동하지 않는다.
