# catalyst-calendar

대시보드 **캘린더 탭**(달력 + 일정 목록)의 원본 `data/catalysts.json`을 관리하는 절차입니다. 2026-11-24 사용자 지시로 만들었습니다.
equity-research 플러그인의 `catalyst-calendar` 스킬(미국 셀사이드용)을 이 프로젝트에 맞게 줄인 것이라, 일정 분류(실적·기업·산업·매크로)만 참고하고 형식은 이 문서를 따릅니다.

## 언제 하는가 (사용자 규칙)
1. **매일 스크리닝 뒤**: 그날 큰 틀 1~3위 테마의 재료에 **날짜가 있는 일정**이 나오면 그 테마 종목으로 이벤트를 추가한다. 일정이 없으면 아무것도 하지 않는다(억지로 만들지 않음).
2. **매일 스크리닝 때 결과 채우기**: 오늘(한국 날짜) 이전에 끝난 이벤트 중 결과가 비어 있는 것을 검색해 결과값을 넣는다.
3. **매달 말**: 다음 달 매크로 일정을 찾아 넣는다. 기준은 스크리닝 날짜가 25일 이후이고 `macroMonths`에 다음 달이 아직 없을 때다. 넣은 뒤 `macroMonths`에 `"YYYY-MM"`을 추가한다.

## 파일 형식 — `data/catalysts.json`
최상위: `updatedAt`(마지막으로 고친 날), `macroMonths`(매크로 일정을 넣은 달 목록), `starRules`(사용자가 바꾼 별점, 아래 참고), `events`(배열).

| 필드 | 필수 | 내용 |
|---|---|---|
| `id` | O | `YYYY-MM-DD-짧은영문` (중복 금지) |
| `date` | O | **현지 날짜**. 달력 칸도 이 날짜에 놓인다 |
| `endDate` | | 여러 날 행사(CES 등)의 마지막 날 |
| `time` | | 현지 시각 `HH:MM`. 모르면 `null` |
| `tz` | O | `ET`(미국 동부) / `PT` / `CT` / `MT` / `CET` / `JST` / `KST` / `CST`(중국) |
| `kind` | O | `macro`(경제지표·중앙은행) / `earnings`(실적) / `theme`(테마 재료 일정) / `market`(휴장·만기) |
| `country` | | `US` `KR` `EU` `JP` `CN` |
| `stars` | O | 중요도 1~3(별 개수). 아래 "중요도(별)" 기준으로 Claude가 1차 판단 |
| `series` | O | 같은 종류 일정을 묶는 키(영문 소문자·하이픈). 예: `us-cpi`, `us-fomc`, `kr-bok`, `earn-micron`, `ces`. 다음 달 같은 지표도 같은 값을 쓴다 |
| `confirmed` | | 공식 출처(발표 기관·회사 공지·거래소 규칙)로 날짜를 확인했으면 `true`, 보조 사이트·보도만이면 `false` → 화면에 "날짜 미확정" |
| `title` | O | 한국어, 무엇의 몇 월 지표인지까지. 예: "미국 11월 소비자물가(CPI)" |
| `frames` | | 관련 **큰 틀** 이름(`data/theme_taxonomy.json`의 `frames`와 똑같이). 틀리면 빌드가 경고 |
| `stocks` | | theme 이벤트: 그날 그 테마로 스크리닝된 종목명 |
| `metrics` | | `[{label, unit, forecast, previous, actual}]`. **발표 전 `actual`은 `null`**. `forecast`·`previous`는 출처를 확인한 경우에만 넣고, 아니면 `null` |
| `note` | | 왜 넣었는지 한두 문장(테마 이벤트는 어떤 재료였는지) |
| `source` | | `{label, url}` 일정 출처 |
| `addedOn` / `addedFrom` | | 넣은 날, 계기(예: `"2026-11-23 스크리닝 1위 로봇"`, `"월간 매크로"`) |
| `result` | | 발표 전 `null`. 발표 후 `{summary, source:{label,url}, checkedOn}` |

- **한국 시간은 적지 않는다.** `build_dashboard.py`가 `date`+`time`+`tz`로 서머타임까지 반영해 `kst`를 계산하고, 화면에 `08:30 ET (한국 22:30)`, 날짜가 바뀌면 `14:00 ET (한국 12/10 04:00)`처럼 표시한다(2026-11-24 사용자 지시: 미국 시간 기준 + 괄호에 한국 시간).
- 한국 일정은 `tz: "KST"`, 시각을 모르면 `time: null`.
- 시각이 다른 시간대로 발표되면(예: 마이크론 MT 14:30) ET로 바꿔 적고 `note`에 원래 시각을 남긴다.

## 화면 색 (2026-11-24 사용자 요청)
달력 색은 **나라 × 종류**로 자동으로 정해지므로 따로 적지 않는다. `country`와 `kind`만 정확히 넣으면 된다.
- 한국 매크로(`KR`+`macro`) / 한국 종목(`KR`+`earnings`·`theme`) / 미국 매크로 / 미국 종목 / 기타 해외(`EU`·`JP`·`CN`) / 휴장·만기(`market`, 회색)
- 해외에서 열리지만 한국 종목 재료인 행사(CES 등)는 열리는 나라(`US`)로 적는다.

## 중요도(별) — 시장 가격에 미치는 영향 순 (2026-11-24 사용자 지시)
- ★★★: 코스피·코스닥 전체를 크게 움직이는 일정. 예: FOMC 금리 결정, 미국 CPI, 미국 고용보고서, 지수 비중이 큰 반도체 대형 실적(마이크론·엔비디아 등)
- ★★: 업종이나 지수에 눈에 띄는 영향. 예: 금통위, 한국 수출입동향, PCE, 소매판매, 일본은행, 선물·옵션 동시만기, 1~3위 테마의 핵심 행사(CES 등)
- ★: 참고 일정. 예: JOLTS, PPI, GDP 잠정치, ECB, FOMC 의사록, 휴장·조기 폐장, 쿼드러플 위칭
- **사용자가 등급을 바꾸라고 하면** `starRules`에 `"series": {"stars": N, "setOn": "YYYY-MM-DD"}`를 추가하거나 고친다. 해당 이벤트의 `stars`도 같은 값으로 고친다.
  - 빌드가 `starRules`를 이벤트 `stars`보다 우선 적용한다. 그래서 그 series의 **이후 일정(다음 달 CPI 등)에도 사용자 등급이 계속 적용**된다. 화면에는 별에 점선 밑줄이 붙는다.
  - 새 일정을 넣을 때 `starRules`에 그 series가 있으면 그 등급을 쓴다. Claude가 다시 판단해 덮어쓰지 않는다.
  - 사용자가 "이번 한 번만"이라고 하면 `starRules` 대신 그 이벤트의 `stars`만 고친다.

## 1. 테마 일정 추가 (매일, 1~3위만)
1. 그날 큰 틀 1~3위 그룹의 `note`와 종목 `reason`에서 날짜가 있는 일정을 찾는다. 예: 전시회(CES·MWC)·제품 공개, 정책·법 시행일, 수주·입찰 결과 발표, 임상 결과 발표(학회), 상장·보호예수 해제, 실적 발표, 정상회담.
2. WebSearch로 **날짜를 확인**한다. 월·일까지 확인 못 하면(예: "내년 상반기") 넣지 않고 보고에 "날짜 미정 일정"으로만 적는다.
3. 같은 행사가 이미 있으면 새로 만들지 않는다. 기존 이벤트의 `stocks`·`frames`에 합치고 `addedFrom`에 날짜를 덧붙인다.
4. `kind: "theme"`이고, 실적 일정이면 `kind: "earnings"`(그 회사 매출·영업이익 `metrics`)로 넣는다.

## 2. 결과 채우기 (매일)
1. 대상: 한국 날짜 기준으로 끝난(`kst` 날짜 또는 `endDate`/`date`가 오늘 이전) 이벤트 중 `metrics`의 `actual`이 비었거나, theme·earnings인데 `result`가 없는 것. 빌드 출력의 `경고(캘린더): … 결과값이 비어 있음` 목록과 같다.
2. 검색해서 채운다.
   - 지표: `actual`에 발표값(숫자만, 단위는 `unit`). 가능하면 `forecast`(발표 직전 컨센서스)·`previous`도 함께.
   - 실적: 매출·EPS(또는 영업이익) 실제값과 컨센서스.
   - 테마 행사: `result.summary`에 실제로 무엇이 발표됐는지 1~2문장(예: "삼성전자가 CES 기조연설에서 휴머노이드 ○○를 공개했다").
   - 공통: `result.summary` 1~2문장(예상 대비 높음/낮음, 시장 반응), `result.source`, `result.checkedOn`(확인한 날).
3. 휴장·만기(`market`)는 결과가 없으므로 채우지 않는다.
4. 발표가 미뤄졌으면 `date`를 새 날짜로 고치고 `note`에 "○/○에서 연기"를 남긴다.

## 3. 다음 달 매크로 일정 (매달 말)
아래를 다음 달 범위로 검색한다. 공식 출처를 우선하고, 확인한 출처를 `source`에 적는다.
- 미국: FOMC(연준 달력)·의사록, CPI·고용보고서(BLS 일정 페이지), PPI, 소매판매, PCE·GDP(BEA), 미국 휴장·조기 폐장
- 한국: 금통위(한국은행), 수출입동향(매월 1일 관행), 코스피200 선물·옵션 동시만기(3·6·9·12월 둘째 목요일, 그 밖의 달은 옵션 만기만), 한국 휴장
- 기타: ECB·일본은행 금리 결정
- 반도체 큰 틀이 1~3위에 자주 드는 동안에는 엔비디아·마이크론·브로드컴 등 주요 반도체 실적도 `earnings`로 넣는다(2026-11-24 첫 적용: 마이크론).
- 규칙으로 계산한 날짜(만기일·의사록 3주 뒤)는 `note`에 계산 근거를 적는다.

## 4. 빌드와 확인
- `python scripts/build_dashboard.py` → 출력의 `캘린더 이벤트 N개`와 `경고(캘린더)` 줄을 확인한다. 형식이 틀린 이벤트는 경고와 함께 화면에서 빠진다.
- 보고에는 추가한 이벤트, 결과를 채운 이벤트(값 포함), 날짜 미정이라 뺀 일정을 짧게 적는다.
- 커밋·푸시는 사용자가 요청할 때만.
