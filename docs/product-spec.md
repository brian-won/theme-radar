# Product Specification & Functional Requirements

> `AGENTS.md`에서 링크되는 기능 명세서입니다. 기능 구현 및 테스트 케이스 작성의 기준(Definition of Done)이 됩니다. 기능 명세 확인이 필요 없는 작업에서는 읽지 않아도 됩니다.

## 1. 시스템 구성 요소 (1단계: 한국 주식 일일 리포트)
- `scripts/market_screen.py`: pykrx로 1차 후보군(느슨한 하한: 150억+/1.5%+)을 넓게 추린 뒤, 당일 조회 시 `scripts/kis_client.py`(KIS API, 모의투자)로 KRX+넥스트레이드(NXT) 통합·애프터마켓 포함 등락률/거래대금을 재조회해 정확한 수치로 교체 → 최종 임계값(500억+/3%+ 캐스케이드) 적용
  - 배경: KRX 정규장(pykrx) 데이터만 쓰면 애프터마켓/NXT 거래분이 빠져 거래대금이 과소 집계됨 (2026-09-14 확인: 영풍 KRX단독 303억 vs KIS 통합 673억) — `FID_COND_MRKT_DIV_CODE=UN` 파라미터로 해결
  - 알려진 한계: 모의투자 API 속도 제한(초당 2건)상 전종목을 KIS로 스캔할 수 없어 pykrx 1차 필터를 통과 못한 종목(정규장에선 등락 미미했지만 NXT에서만 급등한 경우)은 놓칠 수 있음 — 실전투자 키(초당 19건) 확보 시 해소 가능
  - 시가총액 300억 기준은 pykrx 시가총액 기준이라 사용자 HTS 수치와 근소한 차이(약 5~7%)로 경계선 종목이 엇갈릴 수 있음
- 테마/재료 부여(LLM 단계, 미구현): 스크리닝된 종목별로 네이버 금융/증권 뉴스를 검색해 대표 테마명과 상승 이유를 한 줄로 요약
- 테마 그룹핑/순위화(LLM 단계, 미구현): 테마별 평균 등락률·합계 거래대금 계산 → 합계 거래대금 기준 1~3등은 개별 순위, 4등 이하는 전부 "4등"으로 표시 (`reference/테마일지_9월.xlsx`의 `일별주도섹터`/`260105(월)` 시트와 동일 규칙)
- Notion 저장(구현 완료): 데이터베이스 "일일 시황 리포트" (https://app.notion.com/p/1f9031db2a534d0fa751b6a2c94a58e6) — 날짜별 페이지에 시황 요약 속성 + 본문에 테마별 종목 상세 기록
- 2단계(미착수): 실시간 시세/조건검색(증권사 API), 텔레그램/카카오톡 조건 알림, 미국 주식 확대

## 2. 핵심 사용자 스토리
- **US-01**: 사용자는 매일 코스피/코스닥 등락률·거래대금·이동평균 위치를 한눈에 확인하고 싶다.
- **US-02**: 사용자는 그날 거래대금 500억 이상·등락률 3% 이상인 종목을 테마별로 묶어, 어떤 테마가 그날 주도했는지(거래대금 기준 순위) 확인하고 싶다.
- **US-03**: 사용자는 각 종목이 왜 올랐는지(재료) 뉴스 기반 한 줄 요약으로 확인하고 싶다.
- **US-04**: 사용자는 이 리포트를 Notion에서 날짜별로 누적 조회하고 싶다.

## 3. 비기능 요구사항
- 데이터 정합성: pykrx 원본 수치와 스크리닝/그룹핑 결과가 수동 검산(레퍼런스 파일) 결과와 일치해야 함
- 보안: KRX_ID/KRX_PW, 증권사 API 키 등은 환경 변수로만 관리, 코드/문서/Notion에 평문 기록 금지
- 알림(3단계)은 반드시 마지막에 구현 — 조기 구현 금지

## 4. 에이전트 작업 완료 정의 (Definition of Done)
1. 명세서에 정의된 사용자 스토리별 인수 테스트 통과.
2. UI 작업 시 스크린샷/DOM 스냅샷 등으로 실제 동작 검증(짐작으로 "완료" 선언 금지).
3. 관련 API 명세 및 린터 규칙과 일치 확인.
