# Coding Conventions & Linter Rules

> 코드 스타일, 명명 규칙, 커밋 규칙입니다. 언어/프레임워크 기본값과 "다른" 규칙만 적으세요. 기본 컨벤션과 같은 내용은 적지 마세요 — 코드에서 이미 추론 가능해 컨텍스트만 낭비합니다.

## 1. 파일 및 디렉터리 명명 규칙
- {예: 모든 파일/폴더명은 kebab-case}
- {예: 배럴 파일(index.ts)은 각 모듈 최상위에 두고 공개 API만 export}

## 2. 타입/언어 안전성
- {예: any 타입 사용 금지, 타입 추론이 어려우면 unknown + 스키마 검증}
- {예: 모든 유틸리티/핸들러는 반환 타입 명시}

## 3. 컴포넌트/모듈 구조 규칙
- {예: Prop Drilling 3단계 이상 금지, 상태 로직은 커스텀 훅으로 분리}
- {기존 공통 유틸 재작성 금지 — 작성 전 `{경로}` 먼저 검색}

## 4. 에러 처리 규칙
- {예: catch(e){} 형태의 silent fail 금지, 구조화된 예외 로깅 필수}

## 5. Git 커밋 및 PR 규칙
- 커밋 메시지 컨벤션: {예: feat:, fix:, refactor:, docs:}
- 작업 단위: 변경 파일 {N}개 이내, 변경 줄 수 {N}줄 이내 권장
